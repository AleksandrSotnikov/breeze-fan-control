# Участие в разработке

Спасибо за интерес к Breeze. Перед изменениями прочитайте [архитектуру](docs/ARCHITECTURE.md) и [ограничения управления](docs/SAFETY.md).

## Ошибки и идеи

Для обычных ошибок и предложений создавайте issue по шаблону. Сообщения об уязвимостях направляйте приватно по [SECURITY.md](SECURITY.md).

## Работа с кодом

1. Создайте fork и отдельную ветку с понятным названием.
2. Выполните `./build.sh` на macOS arm64. Все 40 текущих проверок должны пройти.
3. Для изменения правил Guardian добавляйте содержательный сценарий с `MockHardware`: особенно для частичной записи, восстановления и временных границ.
4. Сохраняйте SwiftUI-состояние на главном потоке; доступ к одному SMC-объекту должен оставаться последовательным.
5. Не добавляйте произвольные shell-команды, пути записи или внешние зависимости в привилегированный протокол.
6. Обновляйте документацию и `CHANGELOG.md` при изменении поведения.
7. Откройте PR: проблема, итоговое поведение, проверки и границы аппаратного тестирования.

Для обычного вклада реальные записи в SMC не нужны. Не заявляйте поддержку модели на основании одной успешной сборки. Если добровольно проводите аппаратную проверку, укажите модель, ОС, проверенные действия и результат возврата в авто; не публикуйте идентификаторы устройства.

Собранные `.app`, `.build`, `dist`, ZIP-архивы, локальные настройки и токены исключены из Git. Пакет для пользователей публикуется отдельным вложением релиза. Сохраняйте MIT-лицензию и сторонние уведомления.
