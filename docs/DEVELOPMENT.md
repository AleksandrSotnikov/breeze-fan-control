# Разработка и выпуск сборки

[На главную](../README.md)

## Инструменты

- macOS, zsh, Apple Command Line Tools.
- Swift 5.9+ и SDK macOS 14+; сборка использует языковой режим Swift 5.
- `clang`, `swiftc`, `codesign`, `xattr`, `ditto`, `shasum` из системы / Apple tools.
- arm64-компьютер для выполнения собранного приложения и тестов.

Проверить окружение:

```sh
xcrun --find swift
xcrun swift --version
xcrun --show-sdk-path
uname -m
```

Если инструменты не установлены, используйте `xcode-select --install`. Внешние пакеты и доступ к сети самой сборке не нужны. Swift Package Manager, Homebrew и полный Xcode не обязательны.

## Сборка

```sh
./build.sh
```

Результат — `Breeze.app` рядом со скриптом. `.build/` содержит промежуточный объект C и исполняемый файл тестов. Можно вынести промежуточные файлы в другой каталог:

```sh
BREEZE_BUILD_DIR="$PWD/.build/local" ./build.sh
```

`BREEZE_BUILD_DIR` задаёт только место промежуточных файлов: приложение всегда собирается в корне проекта. Относительный путь считается от корня проекта, поскольку скрипт сам переходит в него.

Скрипт создаёт `.app`, компилирует C-мост, два Swift-файла входа с общим `Core.swift`, формирует `Info.plist`, подписывает сначала помощник, затем весь пакет, собирает и запускает тесты. Код завершения ненулевой при ошибке. Собранная цель — `arm64-apple-macosx14.0`; архитектура не выбирается автоматически.

Не пересобирайте пакет, из которого прямо сейчас запущено приложение: сначала завершите его через меню или используйте отдельную копию исходников.

## Проверки

Сборка запускает `Tests/Tests.swift` как отдельный исполняемый файл. Ожидаемый вывод:

```text
PASS: 40 checks; hardware writes mocked, live hardware untouched
```

Проверяются кодеки `flt `, `fpe2`, `sp78`, отклонение NaN, пределы оборотов, незатронутые вентиляторы, остановка, перегрев, потеря датчиков, пауза после сна, устаревший heartbeat, срок сеанса, частичная запись, повторное восстановление и вмешательство прошивки. Проверки используют `MockHardware`. Они не подтверждают совместимость реального SMC и не проверяют всю авторизацию / файловый IPC.

Сборка не запускает приложение и не запрашивает права администратора. Самостоятельно прочитать реальные показания можно без записи:

```sh
./Breeze.app/Contents/MacOS/Breeze --probe
```

Команда выводит JSON с массивом `fans` (`id`, `rpm`, `min`, `max`, `mode`, `target`) и `temperature`. Ошибки идут в stderr; при ошибке возвращается код 1. Это единственный публичный CLI-режим. `BreezeHelper` предназначен для вызова приложением.

## Структура

```text
Source/
  Widget.swift            # UI, чтение датчиков, heartbeat, авторизация
  Core.swift              # SMC, модели, Guardian
  Helper.swift            # отдельный привилегированный процесс
  Bridge/SMCBridge.{c,h}   # IOKit и двоичный протокол
Tests/Tests.swift          # тесты с подставным устройством
scripts/package.sh        # сборка и архив для распространения
Breeze.icns                # иконка приложения
build.sh                   # сборка, локальная подпись, тесты
```

## Подпись и распространение

Ad-hoc подпись создаётся `codesign --sign -`; она не удостоверяет издателя. Developer ID, hardened runtime, entitlement-профили и нотариализация в текущую сборку не включены. Не называйте готовый архив заверенным Apple.

```sh
./scripts/package.sh
```

Скрипт пересобирает приложение, проверяет подпись, создаёт `dist/Breeze-macOS-arm64.zip` без расширенных атрибутов и `dist/SHA256SUMS.txt`. Проверка архива:

```sh
(cd dist && shasum -a 256 -c SHA256SUMS.txt)
```

Упаковка сохраняет обычные права исполняемых файлов; папка `dist/` исключена из Git. Она не включает исходники: они доступны через стандартные архивы GitHub и Git-теги.

## Чек-лист релиза

1. Уточнить версию и номер сборки в `build.sh`, обновить `CHANGELOG.md`.
2. Выполнить чистую сборку и 40 проверок; прочитать ограничения в `docs/SAFETY.md`.
3. Проверить локальный запуск и `--probe` на поддерживаемом устройстве без изменения оборотов.
4. Создать тег версии; приложить архив и суммы к релизу GitHub.
5. Оставлять релиз предварительным, пока ручная запись и восстановление не проверены на реальном оборудовании.
6. В описании указать проверенные модели, версию ОС, отсутствие нотариализации и известные ограничения.

Автоматическая публикация и CI workflow в текущем репозитории не настроены. Команда для внешней CI-среды на macOS arm64 — `./build.sh`; тестам не нужен доступ к физическому SMC.
